# DET Practice Wheel — брифинг для агента (состояние: Legacy 1.2, ноябрь 2026)

Читай целиком перед первым действием. Файл живой: обновляй при смене архитектуры.

## 1. Что это

Веб-рулетка для практики английского (подготовка к Duolingo English Test). Игрок крутит барабан, получает задание (Reading / Writing / Listening / Speaking), отмечает выполнение, получает XP. Карточки игроков соревнуются по очкам.

- **Стек:** Vanilla JS + CSS + разметка в ОДНОМ файле `index.html`. Без сборки, без npm, без фреймворков.
- **Хостинг:** GitHub Pages, репозиторий `m4dsw4ds/det-practice-wheel`, ветка `main`.
- **Прод:** https://m4dsw4ds.github.io/det-practice-wheel/
- **Бэкенд:** Supabase (Postgres + PostgREST). Проект `qjvanbuqrfvbhjjzcwjg`.
- **Ключ:** publishable/anon лежит прямо в `index.html` (`SUPABASE_KEY`). Это нормально для Supabase, но НЕ секрет.
- **Владелец:** русскоязычный, делает приложение для своих детей и друзей (3–10 человек). Вся копирайтинг-часть на русском, игровые термины/названия заданий — на английском.

## 3. Модель данных (Supabase)

```sql
player_data (
  player_id  int primary key default nextval('player_data_id_seq'),
  score      int not null default 0 check (score >= 0),
  stolen_bag int not null default 0 check (stolen_bag >= 0),
  progress   jsonb not null default '{}'::jsonb,   -- {skillId: 0..6}
  inventory  jsonb not null default '[]'::jsonb,
  name       text not null default '',
  avatar     text not null default '🦉',
  token      text not null default substr(md5(random()::text),1,8),
  updated_at timestamptz not null default now()    -- триггером, не клиентом
)

links (
  owner_id  int references player_data(player_id) on delete cascade,
  friend_id int references player_data(player_id) on delete cascade,
  created_at timestamptz default now(),
  primary key (owner_id, friend_id),
  check (owner_id <> friend_id)
)
```

- RLS включён на обеих таблицах; политики `select/insert/update` для `anon` = `true` (открытый доступ).
- **DELETE запрещён** — сброс прогресса делается UPDATE-ом в ноль.
- Сид: игроки 1–3, связи 1↔2, 1↔3, 2↔3.
- Связь двусторонняя: при подключении пишутся ДВЕ строки (`A→B` и `B→A`).

## 4. Как устроен клиент

**Идентичность.** `localStorage.detGame_myPlayer` — id своей карточки. `detGame_host='1'` — режим «общий планшет» (можно писать в любую карточку группы). Нет id → модалка «КТО ТЫ?» (создать карточку / войти по коду).

**Группа.** `friendIds` = `links.owner_id = myId`. Карточки на экране = `[myId, ...friendIds]`. Чужих игроков не видно.

**Права.** `canWrite(id) = hostMode || id === myId`. Чужая карточка — просмотр: тап открывает только панель скиллов (колесо скрыто классом `.game-layout.watching`), сверху плашка `👁 имя — read only`, тап по ней возвращает на колесо.

**Сброс прогресса.** Только активная карточка (`state.p`), с подтверждением по имени. Не «все игроки», не глобальный wipe.

**Настройки.** Change name, Shared tablet, Sync now, Reset progress, Close; под ними мелкие ссылки Diagnostics / Force pull / Force push.

**Самотест.** `?selftest=1` — гоняет UI на фейковом API (реальная база не трогается): рендер карточек, 6 спинов до мастерства, XP-математика, переключение в host-режиме, read-only просмотр, сброс одной карточки. Результат — оверлей PASS/FAIL и `console.log`.

**Синхронизация.**
- `save()` → localStorage + `savedAt` + дебаунс 400 мс → `pushPlayer(state.p)`.
- `pushPlayer` — **upsert** `POST /player_data?on_conflict=player_id` с `Prefer: resolution=merge-duplicates,return=representation`. НЕ `PATCH`: PostgREST молча отвечает 204 на несуществующую строку.
- `bootSync()` — `loadFriends()` → `loadGroup()` (один `GET player_id=in.(...)`) → если есть непушнутые изменения (`savedAt > syncedAt`) не затирает свою строку облаком, а пушит локальное.
- Ошибка сети → чип `🟡 только локально`, ретрай каждые 15 с, баннер с кнопкой «Повторить».
- Индикатор: `#syncIndicator` (чип снизу слева) + `setSyncStatus(mode, detail)`. Клик = автодиагностика `runAutotest()`.
- `?autotest=1` — открыть диагностику сразу.

**URL-параметры.** `?join=<token>` — подключиться к владельцу кода (после создания своей карточки). `?player=N` — легаси, привязка к строке N. `?autotest=1` — диагностика.

## 5. Правила кода (не нарушать без причины)

1. Один файл `index.html`, без сборки — иначе усложнится деплой на Pages.
2. Компактность: не дублировать функции, не плодить абстракции «на будущее».
3. Интерфейс полностью на английском (кнопки, модалки, алерты). Названия заданий/бонусов — английские.
4. Никаких внешних библиотек, кроме Google Fonts и QR-сервиса.
5. Комментарии — по делу, русский.
6. `index.html` деплоится пушем через GitHub Desktop, потом Ctrl+F5 на сайте.

## 6. Известные баги и риски (на момент брифинга)

| # | Серьёзность | Проблема |
|---|---|---|
| 1 | средняя | `?player=N` привязывает устройство к чужой строке без проверки владения. |
| 2 | средняя | `stolen_bag` пишется, но нигде не отображается — мёртвое поле. |
| 3 | низкая | `REPEATS = 16` → 320 DOM-узлов барабана; снижать только с проверкой анимации. |
| 4 | низкая | Фоновая matrix-анимация не останавливается при скрытой вкладке (батарея). |
| 5 | низкая | QR-код через `api.qrserver.com` — внешняя зависимость, при блокировке QR не появится. |
| 6 | низкая | `updateUI()` пересобирает `innerHTML` всех карточек на каждое сохранение. |

Исправлено в 1.2: XSS в именах, запись в базу из автотеста, стили `.modal-title`, наложение баннера/чипа на мобилке.

## 7. Что уже проверено вручную

- SQL-схема, RLS, чтение/запись публичным ключом.
- Upsert создаёт/обновляет строку, `updated_at` серверный.
- Индикатор синхронизации, автодиагностика, Pull/Push/Reset.
- Динамические карточки, «Кто ты?», приглашение по коду, права на запись.

Не проверено на реальных устройствах: iPhone/Android-жесты, вид с 4+ карточками, подключение друга по QR end-to-end.

## 8. Роадмап

**Legacy 1.2 (сейчас):** стабильность, аудит-фиксы, визуал Блок 3 (XP-бар 12px, цифры 1.4rem, инвентарь 42px), хаптика Блок 4.

**2.0:** профиль на устройстве вместо трёх карточек, Supabase Auth для настоящих прав, лидерборд, челленджи 1-на-1, поле `det_url` (ссылка на профиль DET — API у DET нет, интеграция аккаунтов невозможна).

## 9. Операционка

- **SQL:** Supabase → SQL Editor → вкладка должна быть **Database** (не `Logs` — там ClickHouse и синтаксис падает). New query → вставить → Run.
- **Деплой:** GitHub Desktop → Commit → Push → Ctrl+F5.
- **Диагностика:** чип снизу слева или Настройки → «🩺 Проверить синхронизацию». Текст копируется кнопкой Copy.
- **Сброс:** Настройки → «Сбросить прогресс» — обнуляет доступные карточки (в облаке тоже).

## 10. Грабли, на которые уже наступали

1. `PATCH` по фильтру без строки → 204 и тишина. Только upsert.
2. `state.p` может указывать на карточку, которой нет в локальном `state.prog` → всегда `ensurePlayer(state.p)` перед рендером.
3. Старый localStorage (3 игрока, без идентичности) → авто-миграция в host-режим и разовый пуш всех трёх строк.
4. `game_state` (старая таблица «одна строка на всех») удалена из кода полностью — не возвращать.
5. Терминал на машине владельца не работает (`0xC0000142`) — проверять синтаксис вручную либо просить владельца открыть консоль браузера.
