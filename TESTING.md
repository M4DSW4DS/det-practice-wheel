### Регрессии

## Block 5 — Supabase: одна строка = один игрок (Legacy 1.1)

Схема: `player_data`, PK `player_id`, строки 1–3 созданы SQL-ом. Клиент пишет только свою строку upsert-ом.

### Индикатор синхронизации (чип снизу слева)
- [ ] При загрузке: `⏳ сохранение…` → `🔵 в облаке`.
- [ ] Сделал задание: чип на `⏳` и возвращается в `🔵` за ~1 сек.
- [ ] Нет сети / Supabase недоступен: через ~3 сек чип `🟡 только локально` + модалка «Только локально».
- [ ] «Повторить» после возврата сети → `🔵`, локальный прогресс уходит в облако.
- [ ] Клик по чипу открывает AUTOTEST (3 шага, PASS/FAIL).

### Запись только своей строки
- [ ] Игрок 1 крутит колесо → в Table Editor меняются `score`/`progress` только у `player_id=1`.
- [ ] `updated_at` обновился у 1, у 2 и 3 — нет.
- [ ] На планшете переключил на игрока 2, сделал задание → обновилась строка 2, строка 1 не откатилась.
- [ ] Force Push (Настройки) → 3 строки отправлены, алерт «Готово».
- [ ] Force Pull → локальное заменилось облачным (поменяй `score` в Supabase руками → Pull → счёт обновился).

### Два устройства
- [ ] ПК: 3 задания → телефон по QR `?player=1`: тот же счёт за 1–2 сек.
- [ ] Телефон крутит → ПК F5 → счёт совпадает.
- [ ] Одновременно на двух устройствах каждый крутит у себя → прогресс не обнуляется.
- [ ] Телефон по `?player=2` → бейдж и карточка игрока 2, счёт из строки 2.

### Сброс
- [ ] «Сбросить прогресс» → в Supabase все 3 строки `score=0`, `progress={}`.
- [ ] После сброса колесо крутится, прогресс снова пишется.

### Миграция старых данных (однократно на устройстве)
- [ ] Устройство с локальным прогрессом до Supabase: после F5 счёт не обнулился и появился в облаке.
- [ ] Чистый браузер: локальный счёт 0, облачный подтянулся, нули в облако не пишутся.

### Известные ограничения Legacy 1.1
- [ ] Realtime не подключён — PLAYERS обновляется при открытии экрана.
- [ ] Кот в мешке копит в `stolen_bag`, реального воровства нет.
